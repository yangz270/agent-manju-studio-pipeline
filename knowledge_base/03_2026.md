# 2026 视频生成、多模态音画与专项控制手册（模块 03）

> **模块定位**：2026 年的开源视频生成已全面分裂为两大阵营——以 **MiniMax H3、LTX 2.3** 为代表的**“双 VAE 原生音画同出阵营”**，以及以 **Wan 2.2、混元 1.5、Bernini、Scail2、InfiniteTalk** 为代表的**“纯画面高物理/专项控制阵营”**。本手册提供全系模型的节点拆解、双采防崩脸参数、8G 低显存分块方案与超分收口指南。

## 一、 MiniMax H3：8G–16G 漫剧音画同出主力管线

MiniMax H3 是 2026 年开源漫剧生产的头号主力模型，具备**原生音画同出（视频+人声台词/音效同步生成）**与极高的提示词遵循度。

### 1.1 H3 工作流底层结构（与生图流的三大差异）

1. **双 VAE 编解码架构（缺一不可）**：
   - 模型加载区除了 `UNET` 与 `CLIP`，必须同时加载 **`video VAE`（负责画面）** 和 **`audio VAE`（负责声音）**；解码区同样对应两个 `VAE Decode` 节点，最后汇入单节点 **`创建视频（Create Video）`**（设为 **24 fps、H264-MP4**）。
2. **采样区拆分为五件套**：
   - 将传统 K 采样器拆解为：`随机噪波（Seed）` + `基本引导器（Guider）` + `基本调度器（Scheduler/步数）` + `K采样器选择` + `自定义 Sigma 值`（支持手调去噪曲线）。
3. **四项核心提速与画质改造（必加）**：
   - **① 加速 LoRA**：挂载 `MiniMax 600 EMA` 加速 LoRA（权重 **`0.8`**），或最新 **H3 四步加速 LoRA + 双时钟采样节点**（速度直接提升约 40%，且画质更稳）；
   - **② 去油腻 LoRA**：挂载去油腻 LoRA（权重 **`0.4`**），消除生成人物皮肤的塑料油光感；
   - **③ 注意力加速节点**：串联在模型与基本引导器/调度器之间；
   - **④ 低显存神器（模型分块节点）**：专为 8G / 12G 显存（如 RTX 3060）设计，将模型数据切块串行处理，**分块数可填 `2 / 4 / 8`**（数字越大显存占用越低，但速度相应变慢；24G+ 显卡无需开启）。

### 1.2 H3 双采多参工作流（防远景崩脸 + 降抽卡成本核心机制）

为什么漫剧出片强烈建议用**双采（两阶段采样）**而不是单采直出？
- **原因一（修远景崩脸）**：H3 在低像素单采时，一旦人物远离镜头（中景/远景），面部像素不足就会触发“无限崩脸”。二采在一采结果上做潜空间高清放大，能稳稳锁住中远景人脸。
- **原因二（省抽卡时间）**：5060Ti 16G 单采直出一条 80 万像素视频需 15–20 分钟，若动作不对就白等；双采**一采只跑 `0.3MP（30 万像素）`**，几分钟即可验看构图与表演，不满意立刻点取消改提示词，满意再跑二采放大到 `0.8MP–1.5MP`。

#### H3 双采多参标准配置表

| 配置项 | 标准设定值 | 关键工程操作说明 |
| :--- | :--- | :--- |
| **多参考图配比（4 张起）** | `图 1`：**全景环境+角色站位参考图**<br>`图 2–4`：**各出场角色的三视图/四宫格资产图** | 用不到的参考图模块选中按 `Ctrl+B` 旁路关闭；若某输出节点报红框但前面未接线，直接 `Ctrl+B` 关掉即可，不影响主流程 |
| **音色参考输入** | `uploadaudio` 节点 → `Set/Get` → 连入 **`参考音频`** 端口 | 锁死跨段落同一角色的说话音色（无台词镜头可 `Ctrl+B` 禁用该组）。首次无参考音频时先裸跑一段长台词，只导出音频截作全剧音色母本 |
| **步数分配（分离 Sigma）** | 总步数 **12 步** → **`8 步给一采` + `4 步给二采`** | 若片中远景多、需极力保脸，可将二采降噪步数从 2 步调高至 **3–4 步**（耗时增加约 300 秒，清晰度显著提升） |
| **音视频潜空间分离放大** | 必加 **`H3 AV Latent Separate / Merge`** 节点 | **极其重要**：潜空间放大节点只能放大视频画面，严禁连同音频一起放大（否则声音畸变）！必须先分离出视频 Latent 放大，再与原音频 Latent 合并送入二采 |
| **像素量（MP）与时长配比** | 一采 **`0.3`（30万像素）** → 二采 **`0.7–0.8`（70–80万像素，约 11–15 分钟）**；5 秒单镜二采可拉至 **`1.5`（150万像素）** | 像素口径换算：`0.4 = 480P`、`0.5 ≈ 960×544`、`1.0 ≈ 1376×768`。本地跑片**单次严禁贪长超过 10 秒（约 2 个镜头）**，5 秒单镜最稳 |
| **首帧 / 首尾帧兼容用法** | `图像转视频` 节点：接 1 张图 = 图生视频；接 2 张图 = 首尾帧 | 首尾帧两张图尺寸不一致时，中间必须加 **`图像缩放` 节点统一到 `1.5MP（150 万像素）`**，否则画面必抖动变形 |

> **两份 H3 影视工作流怎么选？**
> 日常批量出片追求效率选 **「H3 二采视频工作流」**（一采分辨率不动，只调二采像素）；重头戏、打戏或特写追求极致画质选 **「H3 官流改高质工作流」**。提示词虽支持中文，但 **H3 对英文提示词理解更精准**，建议先用智能体出中文审稿，确认后再转英文规范格式喂入 ComfyUI。

## 二、 LTX 2.3：时间轴导演台与多模态全能工作流

LTX 2.3 是另一款原生支持音频生成的全能型多模态视频模型，相当于把“多镜头生成 + 配音对口型 + 视频延长 + 去水印字幕”集成在一个工作流内。

### 2.1 模型清单与两阶段省显存架构

1. **核心组件（注意版本兼容性）**：
   - **双 CLIP 加载器**：`Gemma-3-32B`（**必须选 FP8 版**，FP4 版存在严重不兼容风险）+ `LTX2.3 text projection`（均放入 `models/text_encoders`）。
   - **主模型**：日常 16G–24G 显存选 **`LTX2.3 蒸馏 1.1（FP8）`**（原版 42.98GB 需 24G+ 甚至 32G 显存）；非蒸馏版挂载蒸馏 LoRA 后也可降至 4 步。
   - **双 VAE**：`video VAE` + `audio VAE`（注意：若手动删掉 `audio VAE` 只跑静音视频，**必须把连接它的音频预览节点一并删掉**，否则必报错）。
2. **两阶段采样机制（省显存核心）**：
   - 第一阶段生成时，通过 `LTXVDirectGuide` 节点将分辨率设为 **`scale_by 0.5`（宽高砍半）** 完成初步去噪；
   - 第二阶段调用专属 **`latent 放大模型`** 将潜空间 `×2` 还原至原始分辨率（如 1080×720）再做精采样，显存占用暴降而画质不减。

### 2.2 核心控制器：`LTX Director（导演台）` 四大玩法

- **玩法 1：时间轴分段提示词编排（一镜到底/多镜切换）**
  导演台上方为**时间轴分段提示词**，下方为**全局提示词**，可设定总时长（如 5.21 秒）、帧率与宽高。调整某一段时长时相邻段会自动联动（时间轴末尾黑色区域代表不生效区间）。配合流内**实时预览节点**，生成中途发现画面不对可立即中断止损。
- **玩法 2：图生视频 / 首尾帧 / 多帧接力**
  在时间轴上删掉纯文本块，将单张图片拖到指定秒数（如 3 秒处）即为图生视频；把两张图分别卡在时间轴首尾两端、中间填动作描述即为首尾帧；继续往后追加图片与文本即构成**多帧连续参考**。
- **玩法 3：视频无缝延长与音频驱动数字人**
  - **视频延长**：将已有视频当作“首帧图”上传，后面接文本描述，模型会**连画面带音轨一起往后顺延生成**，且人物嘴型自动对齐新生成的台词。
  - **对口型（Talkie）**：上传 1 张人物图 + 1 段干声轨（挂 `talkie LoRA`），直接生成口型与微表情精准对齐的数字人视频（注意：不可直接上传无音轨视频要求配口型）。
- **玩法 4：IC 视频编辑模式与实用除杂 LoRA 套件**
  切换到 IC 模式并在第 3 个 LoRA 槽位挂载功能 LoRA，可实现局部编辑；更实用的是官方附赠的 **四大工具 LoRA**：**`去水印`、`去字幕`、`模糊变高清`、`抽帧`**——将“去水印 LoRA + 去字幕 LoRA”串联，即可一键洗掉素材视频上的飘字与台标。

## 三、 纯画面生成与专项控制模型矩阵（Wan 2.2 / 混元 / 专项流）

此类模型**均不具备原生音频生成能力**（需后期配音），但在物理规律、复杂运镜、多人同框或动作迁移上各怀绝技：

### 3.1 Wan 2.2（高低噪双模） vs 混元 1.5 AIO vs Small Mist 2.0

| 模型方案 | 核心架构与模型配置 | 采样参数铁律 | 实测长板与选型判据 | 致命红线（踩中必崩） |
| :--- | :--- | :--- | :--- | :--- |
| **Wan 2.2 原生双模流**（T2V / I2V / 首尾帧） | **高噪生成模型 + 低噪补细节模型**（双 FP16/BF16）+ `umt5-xxl`（CLIP Type 必选 **`wan`**）+ **复用 `wan2.1 VAE`** | 挂 `lightx2v` 4 步加速 LoRA → 两个 KSampler 各跑 2 步（`0–2` 与 `2–4`），**CFG: 1**。<br>T2V 采样器禁改；**I2V 采样器必改 `uni_pc` + `simple`** | **物理合理性全网第一**（甚至能自动脑补出一个人来扶住快倒下的西瓜），细节完整度与风格化生态最强。<br>帧数换算：`81帧 ÷ 16fps = 5秒`；`121帧 = 7秒` | 1. **High/Low 两个 4 步 LoRA 严禁装反**（装反必出满屏马赛克/彩色杂点）；<br>2. **首尾帧模式必须用 BF16/FP16 底模**（FP8 控制精度不够会崩）；<br>3. 首尾帧两图必须用 `按宽高比缩放（限1024）` 统一尺寸比例。 |
| **混元 Video 1.5 AIO**（对比 Wan 2.2 Mega V12.1 AIO） | AIO 整合加速单模型（下 Wan AIO 时认准带 **`Mega`** 前缀的新版） | 1280×720，AIO 4–6 步快速采样 | **复杂运镜指令响应度显著胜出**（推进、360°环绕、仰拍上升均严格执行），画面色调更自然真实 | 细粒度物体常漏画（如提示词里的雨滴、太阳易丢），偶发人物中途变脸的结构性错误（稳定性不如 Wan 2.2）。 |
| **Small Mist 2.0**（Civitai 开源动漫/风格化强模） | 基于 Wan 衍生，用 **FP8 底模** + **`wan2.1 VAE`**（4060Ti 16G 可跑 480×720 / 81帧） | **实测最佳组合：`Euler a` + `Normal` + `6 步` + CFG 1**（优于官方推荐的 `UniPC + Simple`） | 官方 `UniPC` 画面易浮空失重；改用 **`Euler a + Normal + 6步`** 后动作连贯、物理重力感极强、穿帮极少；动漫与风格化表现惊艳 | 真人写实脸部表现一般，专攻二次元与风格化大动态镜头。 |

### 3.2 三大专项控制工作流（多人同框 / 动作迁移 / 数字人口播）

1. **Bernini（字节开源，基于 Wan 2.2）：本地版“即梦 2.0”多人同框与视频编辑**
   - **三大模式**：`RV2V 多图参考`（最省显存，专治多角色同框互动）、`V2V 视频编辑`（改视频背景/换发色）、`RV2V 参考视频编辑`（极吃显存，建议上云）。
   - **安装与提示词铁律**：需通过 Git Clone 安装 `Bernini Studio` 节点、搭配 `KJNodes（PatchSageAttn 加速）`。写提示词时遵循固定模板：`image0 的 [角色A] 和 image1 的 [角色B] 正在…`——**注意第一张图的索引永远是 `image0` 而不是 `image1`！**
2. **Scail2 (V2)：动作迁移与人物替换（换人跳舞 / 武打替身）**
   - **代际跃升**：V2 版本彻底修复了 V1 严重的脸崩问题，已达商业可用标准（50 系显卡可选专属 `MXFP8` 权重）。
   - **遮罩链路**：使用 **`SAM3`**（放 `checkpoints`）输入 `person` 自动追踪视频与参考图中的人物，通过 `Get Person Mask` 输出红/蓝双色标注遮罩喂给 `Wan Scail2 to Video` 核心节点。
   - **两大实战技巧**：
     - **只要迁移动作、不想保留原视频背景？** 直接把连向核心节点的 **两个 Mask 输入线断开** 即可！
     - **成片人物边缘有白边 / 光影不融合？** 白底参考图必须先开 `图像背景移除` 去背；长视频延长时挂上 `color transfer` 子节点自动匹配背景色调与光影。16G 显存开启 `WanVideoBlockSwap（分块数 2）`。
3. **InfiniteTalk（优先选 KJ 版）：单图 + 音频驱动长口播 / MV**
   - **原理**：在 `wan2.1 I2V FP8` 底模上挂载 `infinitalk mo / single` 两个附加激发模型，用 `wav2vec` 提取音频特征驱动口型。
   - **无限长视频切块机制**：采用 **`81 帧一块 + 9 帧重叠（Overlap）`** 策略，15 秒以上的长音频会自动切块生成并裁掉重叠帧无感拼接。
   - **必做前置动作（人声分离）**：输入的音频如果带有 BGM 音乐或伴奏旋律，会严重干扰数字人的头部动作与口型！必须在流内先经过 **`人声分离节点`** 提取纯干声再喂入模型。16G 显卡将 `WanVideoBlockSwap` 设为 **30 左右**（设 48 为全卸载到 CPU，最省显存但最慢）。

## 四、 视频与图像超分放大收口：FlashVSR 1.1 vs SeedVR2

视频生成的直出分辨率通常在 480P–720P（40万–80万像素），成片交付前最后一步是用 2026 新一代扩散超分模型画龙点睛：

| 对比维度 | FlashVSR 1.1（务必用 1.1，优于 1.0） | SeedVR2（7B 平衡版 / 7B-S 重细节版） |
| :--- | :--- | :--- |
| **模型档位与目录** | 分小/中/满血三档，文件夹名严格区分大小写（`FlashVSR-v1.1`） | 选 **7B（Q4 量化或 FP8/Q8）**，3B 版效果弱不推荐；VAE 需单独加载 |
| **省显存核心机制** | 同时勾选开启 **`VAE 分块` + `Latent 分块`**（将整帧切成九宫格逐块放大再拼接，**显存占用直降为原来的 1/9**，画质无接缝） | 通过 `resolution` 设定输出最小边；注意 **`batch size`（默认 5）极吃显存**，低显存需调小 |
| **视觉质感差异** | **线条与边缘更锐利**，但细看皮肤与背景会有一定的**平滑涂抹感** | **细节还原与无中生有能力极强**，真实皮肤毛孔、发丝光泽、老照片/老视频修复完胜 |
| **一句话选型结论** | **二次元漫剧、追求画面干净锐利、8G–12G 低显存机器 → 选 FlashVSR 1.1** | **真人写实短剧、面部特写多、修复模糊老素材、16G–24G+ 机器 → 选 SeedVR2 7B** |
