## 二、 核心时效性与版本代际演进（2024–2026 必读避坑）

ComfyUI 生态在 2025 至 2026 年经历了从“传统扩散模型（SD 1.5 / SDXL）”向“原生多模态 DiT + 蒸馏加速架构”的断代式跃迁。**直接拿旧版经验套用 2026 新模型，是导致画面崩坏、节点报错、显存爆炸的头号原因。**

### 2.1 架构与参数跨代际对比表

| 核心维度 | 旧世代标准（SD 1.5 / SDXL 传统流） | 2026 新世代标准（Turbo / DiT / 多模态流） | 跨代际混用后果与版本要求 |
| :--- | :--- | :--- | :--- |
| **模型加载方式** | 单一 `Checkpoint 加载器` 同时吐出 MODEL / CLIP / VAE 三根线 | **三件套分离加载**：`UNET 加载器`（diffusion_models）+ `CLIP 加载器`（text_encoders）+ `VAE 加载器`（vae） | 新模型无合并 Checkpoint；放错子目录或选错 `CLIP Type`（如 Lumina / C2 / wan）会直接报错或静默失效 |
| **音视频解码架构** | 仅支持单一图像/视频 `VAE`，无原生声音能力 | **音画双 VAE 架构**：MiniMax H3、LTX 2.3 均采用 `video VAE` + `audio VAE` 双路编解码 | 漏装或漏连 `audio VAE` 工作流无法运行；潜空间放大时必须用 `AV Latent Separate` 仅放大视频流 |
| **采样步数（Steps）** | 原生 20–30 步（超过 50 步无收益且易崩） | **4–12 步**（原生蒸馏模型 4–9 步，或大模型挂载 `lightx2v` / `EMA` 四步加速 LoRA） | 在加速模型上强跑 30 步不仅浪费数倍算力，还可能引起画面过曝与结构畸变；但**带密集小字的海报严禁开加速 LoRA**（需退回 25–40 步慢跑） |
| **引导系数（CFG）** | SD 1.5 常用 **6.5–8**；SDXL 常用 **5–6** | **严格锁死为 1**（Z-Image-Turbo、Krea2、Boogu、Wan 2.2 加速流等均适用） | **模型越强，CFG 必须越低**。在 2026 Turbo 模型上把 CFG 拉到 7 会导致严重过拟合（画面极度锐化、色彩爆炸、变抽象画） |
| **负面提示词机制** | 必填通用负面词（`easynegative V2` 或 `One Button Prompt`），能将画质提升一个档次 | **全面弱化或省去**：直接用 `Conditioning Zero Out（条件零化）` 占位，或内置于模型中（如 Flux、Boogu、Krea2） | 新模型强行堆砌旧版负面词无正向收益；但节点存在负面输入口时不可悬空，必须接 `条件零化` 节点防报错 |
| **舒适分辨率红线** | SD 1.5 严格限制 **≤ 768×768**；SDXL 约 **1024×1024** | Krea2 / Flux 支持 **1K–4K（1088×1920 至 2000px+）直出**；视频以“百万像素（MP）”计量（0.3MP–1.5MP） | 用 SD 1.5 直出 1024px+ 必出“双头/多张脸拼接”；而 Krea2 编辑节点（`C2 Edit`）有 **200 万像素上限**，输入图必须前置缩放到最长边 1600 |
| **提示词语言支持** | 仅识别英文词组（Tag 堆砌），中文直接乱码或被忽略 | 国产模型（Z-Image-Turbo、Qwen-Image 2.1、Wan 2.2、MiniMax H3）**原生支持中文自然语言**；Flux / Krea2 仍以英文自然语言最佳 | Krea2 内部嵌有基于 CLIP 的 LLM 提示词扩写子流，虽能跑中文，但写英文才能发挥最高艺术风格还原度 |

### 2.2 角色资产与图像编辑的三代技术更替

在漫剧生产最核心的“角色一致性与多视图资产”环节，教程语料中存在明显的前后迭代，**请直接采用 2026 最新第三代方案**：

1. **第一代（已废弃）：Krea2 + 横版四视图 LoRA**
   - **淘汰原因**：横版排布（正+正侧背）中，**侧脸占用的像素面积极小**，喂给视频模型时根本无法提供有效的侧脸参考；且 Krea2 自带四视图 LoRA 结构老旧，编辑节点 `C2 Edit` **最多仅支持 2 张参考图**，无法处理三人及以上同框。
2. **第二代（单人高一致过渡）：Flux Kontext（Pro / FP8 / GGUF）与 Flux2-Klein（9B）**
   - **技术特点**：Flux Kontext 能从单张正面图推算侧面与背面，基本取代了繁琐耗时的单角色 LoRA 训练（16G 显存用 FP8 版，12G 显存用 GGUF 版）；Flux2-Klein 主打 9B 轻量 3 秒快改。但两者对多图融合（>2 张）依然受限，且 Flux Kontext 强制要求全英文精确指令。
3. **第三代（2026.09+ 现行主力）：Krea2 风格全身图 + Qwen-Image 2.1（或 2511 BF16）多图编辑流**
   - **终极工作流**：利用 **Krea2** 强大的风格化生态先跑出 1 张“纯白背景、全身正面直视镜头”的角色基底图 → 送入 **Qwen-Image 2.1 图片编辑流**（支持多达 **10 张参考图**），配合“白膜三视图/四宫格模板图”生成 **新版三视图或 2×2 四宫格角色资产图**（四宫格中故意裁掉右下角全身图的小脸，逼迫模型只参考大图五官）。

### 2.3 环境版本、整合包真伪与安全红线

1. **伪官方整合包辟谣与安全警示**：
   - 市面上宣称“ComfyUI 官方最新发布 V9.5 中文整合包（含 200+ 工作流）”实为第三方搬运号拼凑包（实测仅 56 个调通工作流），**ComfyUI 官方从未发布过中文整合包，也不存在 V9.5 官方版本号**。
   - **安全准则**：第三方整合包内含完整 Python 运行时与数百个自定义节点，**节点代码拥有本机同等系统权限**。严禁在存放核心商业机密或网银环境的裸机上运行来源不明的整合包；推荐使用秋叶原版启动器 + 官方/开源社区可信工作流。
2. **ComfyUI 内核与节点版本要求**：
   - **内核必须保持 2026.09 之后版本**：使用 `Qwen-Image 2.1` 专属节点、`LTX 2.3 Director`、`Wan 2.2`、`MiniMax H3` 等新组件时，若下拉菜单找不到对应节点或 CLIP 类型，必须打开启动器「维护中心 → 版本更新」升级 ComfyUI 内核。
   - **严禁开启「节点 2.0（Node 2.0）」**：左上角设置中的“节点 2.0”属于测试版 UI，开启后会导致大量核心自定义节点无法显示或连线异常，务必保持关闭。
   - **版本分支策略**：启动器版本管理固定选择 **稳定版（Stable）**，1–2 个月按需更新一次，切勿盲目追新每日开发版（Daily Build）。
3. **路径与目录铁律**：
   - 解压路径必须为**浅层、纯英文路径**（严禁包含中文字符、全角符号或过长嵌套目录，否则必报路径找不到或编码崩溃）。
   - 模型权重必须严格对号入座放入 `ComfyUI/models/` 下的对应子目录，且文件夹大小写不可拼错（如 `model_patch`、`FlashVSR-v1.1`）。

### 算力效率黄金法则

1. **一采买保险，二采出成片**：跑视频永远优先用 **双采工作流**。一采在 `0.3MP（30 万像素）` 下只需几分钟即可看清构图、动作与脸部是否崩坏；确认无误再进入二采放大到 `0.8MP–1.5MP`，彻底杜绝“苦等半小时抽出一张废卡”。
2. **养成“吸尘器”清显存习惯**：ComfyUI 顶部菜单栏的两个“吸尘器”图标代表**释放显存与内存缓存**。每跑完一批大图或一段视频后顺手点一下（或在流中合理配置缓存节点，注意 Krea2 流内嵌清理显存节点反而拖慢速度，建议手动点），可减少 80% 的无故 OOM 报错。
3. **能本地跑 ≠ 值得本地跑**：在漫剧量产阶段，16G 显卡跑一条 10 秒视频需 15 分钟，而云端（RunningHub / 租卡）同样约 15–17 分钟且不占本机。最佳实践是 **“本机调通一采框架 + 云端与本地双开跑二采成片”**，两边择优进剪映合成。
